# 決済端末での手検出カウント PoC(社員証をかざす手、案)

**背景**: `face_count_poc`(人物のライン通過検知)や本番の`nokosahen_checkout`は
近接フィルタ・一方向判定を絞り込んでも、決済の実カウントとして十分な精度が
出ない可能性がある。その場合の代替案として、「人全体がラインを通過したか」
ではなく「決済端末に社員証をかざす手が現れたか」を直接見た方が、誤検出
(通りすがりの人・行列で待つ人を誤ってカウントする等)が減るのではないか、
というアイデアを試すための試作PoCです。

**このフォルダだけで完結**していて、ROS2やプロジェクト本体には一切依存しません。
このフォルダごと送れば、受け取った人はこれだけで試せます。

## 重要な注意(このPoCの限界)

**「本当に社員証を持っているか」までは判定していません。** MediaPipe Handsで
手を検出し、決済端末の読み取り位置とみなす画面内の矩形(ROI)にその手が
一定フレーム数とどまったら「かざした」とみなして数える、という**プロキシ
(代理)判定**です。

- 手ぶらでその位置に手をかざしても検知されてしまう(社員証の有無は見ていない)
- 逆に、本当に社員証をかざしても、位置がROIから外れていれば検知されない
- 「読み取りの成功」と連動させたい場合は、決済端末側の実際のセンサー
  (ICカードリーダーの読み取り成功シグナル等)と組み合わせる方が確実
- あくまで「手の出現回数を数える」という代替アプローチ自体が使い物になるか
  (人物ライン通過方式より誤検出が減るか)を確認するためのもの

## 準備

```bash
pip install -r requirements.txt
```

MediaPipeはRaspberry Pi(aarch64/arm64)でも比較的軽量に動く(YOLOv8+PyTorchより
CPU負荷が低いことが多い)ため、決済カメラ側の処理が重い場合の代替案としても
検討する価値がある。

## 実行

```bash
python badge_hand_poc.py
```

**カメラは自動検出されます**(他のPoCと同じ方式。`--camera`で明示指定も可能)。

決済端末の実際の読み取り位置に合わせてROI(検知対象の矩形)を調整する:

```bash
# 画面比率で指定(左上X 左上Y 幅 高さ、それぞれ0.0〜1.0)。既定は画面中央。
python badge_hand_poc.py --roi 0.35 0.4 0.3 0.35
```

その他のオプション:

- `--min-hits 5` : この回数だけ連続でROI内に手を検出できたら「かざした」と確定する(誤検出対策)
- `--cooldown-sec 1.5` : 1回カウントしてから次のカウントまで最低これだけ間隔を空ける(同じ手を連続で数えないため)
- `--min-detection-confidence 0.6` : MediaPipe Handsの検出信頼度の下限

## 終了方法

映像ウィンドウを選択した状態で `q` キー。

## 見るべきポイント

- 決済端末に手をかざしたときだけ`【検知】社員証をかざす手を検知！`と表示されるか
- 手を出し入れするだけで(社員証を持たずに)誤って数えてしまわないか
  (→この方式の限界そのものを確認するポイント)
- 通りすがりの人の手がたまたまROIをかすめて誤カウントしないか
- 人物ライン通過方式(`face_count_poc`)と比べて、実際に精度・使い勝手が
  良くなっていると感じるか

## 既知の制約

- 社員証の有無そのものは判定していない(手の位置だけを見るプロキシ判定)
- 手袋・極端な角度・暗い環境ではMediaPipe Handsの検出精度が落ちる
- 2人が同時に手を出すと、どちらの手か区別せず「ROI内に手がある」ことしか見ない
- あくまで「この方式で使い物になるかどうか」を判断するためのPoCであり、
  そのまま本番に組み込む前提のコードではない
